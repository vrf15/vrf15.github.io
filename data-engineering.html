Data Engineering

Data Engineering focuses on the pipelines, storage layers, transformations, and infrastructure that prepare data for analytics, dashboards, reporting, machine learning, and downstream systems.

Overview

My data engineering work focuses on moving external data from raw sources into structured, analytics-ready systems. Across my projects, I have built pipelines that use API ingestion, orchestration, cloud storage, relational databases, and dbt-based transformations.

The goal is to create repeatable workflows where raw data can be collected, validated, cleaned, modeled, and prepared for dashboards, reporting, deeper analysis, machine learning preparation, or other downstream systems.

Pipelines

My pipelines usually follow a consistent structure: API ingestion, orchestration, storage, transformation, and final modeling.

Airflow Orchestration → API Ingestion S3 Lake RDS PostgreSQL → dbt Transformation → raw → stg → core → mart

External data is collected through API requests, then scheduled and controlled through Apache Airflow. Depending on the project, extracted data is loaded into cloud storage, database tables, or both. dlt is used where applicable to support extraction and loading workflows.

Schema pattern

raw → stg → core → mart

raw

I use the raw layer to preserve source-shaped ingested data.

staging

In stg, I focus heavily on casting, renaming, standardizing, and making fields uniform before they move deeper into the warehouse.

core

In core, I build more reusable modeled tables and add safety nets, checks, and flags to understand what types of imperfect or unclean data are still passing through. This helps explain possible skews later in marts, dashboards, analytics, or model-ready datasets.

mart

The mart layer is generally dashboard-ready. Sometimes I break fact tables into smaller marts for focused dashboards, and other times I create datasets specifically prepared for machine learning workflows.

Tools Used

dlt

Used to support extraction and loading workflows, especially when moving API-based source data into structured storage or database layers.

dbt

Used for SQL-based transformations, staging models, core models, mart tables, testing patterns, and building analytics-ready datasets.

Apache Airflow

Used to orchestrate pipeline runs, schedule ingestion jobs, control task order, and make workflows repeatable.

Docker

Used to containerize project environments, keep dependencies consistent, and make local development or deployment workflows easier to reproduce.

EC2

Used as cloud compute infrastructure for running project services, development environments, and pipeline-related workloads.

S3 Lake

Used as object storage for raw or semi-structured data before it is loaded, modeled, or transformed further.

RDS PostgreSQL

Used as the relational database layer for storing ingested data, transformed tables, and analytics-ready schemas.
